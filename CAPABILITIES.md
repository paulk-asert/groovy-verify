# Capabilities

The full inventory of what groovy-verify proves today, by phase — each row a capability, how you author it,
and its status, including the "deferred"/"residual" notes that mark the honest boundaries. For the summary and
the worked examples, see [README.md](README.md#whats-demonstrated); for what the engine *can model* (the in/out
boundary), [FRAGMENT.md](FRAGMENT.md); for the increment history, [ROADMAP.md](ROADMAP.md).

| **Ticket-lock mutual exclusion (Leino KRML260, bounded process set)** | The safety half of *Modeling Concurrency in Dafny*: a bakery-style mutual-exclusion lock, modelled the paper's way — each atomic event over a system invariant `valid`, **mutual exclusion proved as a consequence** of the invariant, and **every event proved to preserve it**. `Process` is a fixed enum `{A, B}` (Leino sanctions `datatype Process = Agnes | …`), so `cs`/`t` are enum-keyed maps and the `∀p`/`∀p,q` conjuncts expand over the finite domain; events are Model-2 two-state predicates discharged as empty-bodied lemmas (the lattice/monoid-law pattern), sidestepping mutable-map-field framing. The paper's exact `mutualExclusion` lemma — two **symbolic** processes `p, q`, concluding `p == q` — verifies: a symbolic-key read `cs[p]` connects to `valid`'s literal-key reads via the enum domain-closure axiom + array extensionality, so **one lemma covers every process**. `Request`/`Enter`/`Leave` each preserve `valid` (`Leave` — advancing `serving` while re-establishing the strict lower bound for a waiter — is the trickiest, needing *both* uniqueness and `eating ⟹ served`). Teeth: drop the uniqueness conjunct (the strengthening the paper adds last) and both mutual exclusion and `Leave`-preservation refute. This SMT-**proves** the mutual-exclusion invariant the "concurrency lite" gallery disclaims and hands to the runtime rungs — a complement, not overlap. *(Liveness followed — Phases 171–175, the rows below; the general-N formulation landed in Phase 198: int-indexed processes over a symbolic count, quantified `valid`.)* | ✅ Phase 170 |
| **Ticket-lock liveness ranking function (Leino KRML260 §7.6)** | The start of the *liveness* half — *a hungry process eventually eats*, which Leino proves by a well-founded measure `t[p] - serving` a proof-loop drives to zero (the liveness proof **is an algorithm**, so a sequential SMT checker can reach it — no temporal-logic engine). Empty-bodied lemmas over the same bounded (enum) state establish the ranking function: it's **bounded below** (`>= 0` for any waiter), **strictly decreased by `Leave`** (and kept `>= 0` — needing *both* uniqueness and `eating ⟹ served` to know a distinct waiter holds a larger ticket) and **unchanged by every other event** (so only `Leave` moves it, downward), a **currently-served process always exists** while someone is hungry (Leino's `TicketIsInUse` strengthening → `CurrentlyServedProcess`, keeping progress available), and **measure zero enables** the `Hungry → Eating` transition (the base case). Dropping uniqueness refutes well-foundedness; dropping `TicketIsInUse` refutes served-process existence. *(These are the ingredients; Phases 173–175 compose them — bounded, then fair-schedule base case, then the complete two-process theorem.)* | ✅ Phase 171 |
| **Ticket-lock bounded bypass (bounded overtaking)** | The liveness result that ships after the full temporal *eventually-eats* hits the trace-composition/induction wall (probed and located in Phase 172: per-step trace reasoning and bounded-`∀` instantiation verify, but induction over a symbolic horizon and chaining implication-guarded transitions do not). With the **counting invariant** `ticket - serving == (#non-thinking processes)` — maintained by every event (`Request` +1, `Leave` −1, `Enter` unchanged) — a waiter's measure `t[p] - serving` is **≤ 1** for the two-process lock: **a waiting process is overtaken at most once before it enters**, a liveness property *stronger* than mere eventual entry (it bounds the wait). Composed with Phase 171 (each `Leave` decreases the measure): from any `Hungry` state at most one competitor `Leave` stands between the waiter and eating. A **state invariant**, so it needs no trace/fairness machinery. Dropping the counting invariant refutes the bound (the dispenser could run arbitrarily far ahead). *(The temporal composition followed in Phases 173–175; this bound is also what makes the composed liveness a two-case split rather than an unbounded loop.)* | ✅ Phase 172 |
| **Trace-level bounded liveness (higher-order `apply` over time)** | An engine fix makes a numeric-returning `Function`'s application `f.apply(i)` a **stable, shared Int-sorted** uninterpreted-function term (previously the `int` argument was coerced into the `Object` value sort, so `f.apply(i)` fell through unmodelled — a fresh opaque value per occurrence, defeating composition).
